1. Visão geral
Sistema web para planejar móveis planejados de forma paramétrica: o marceneiro deﬁne as
dimensões do módulo, divide em vãos, coloca prateleiras, gaveteiros e portas, e o sistema
evolui até gerar plano de corte, arquivos de máquina, orçamento automático e contrato.
Dois painéis distintos:
1. Painel de Insumos: cadastro de chapas MDF, ﬁtas de borda e ferragens (com preço e
estoque).
2. Painel de Projetos: montagem 3D dos móveis consumindo os insumos cadastrados.
Fluxo do software de referência analisado: Estrutura (L/A/P, divisões, internos, portas) →
Aparência → Visualizador 3D → Orçamento (plano de corte com % de aproveitamento,
export Excel/DXF/XML) → Contrato de compra → Vista explodida numerada.
2. Stack e arquitetura
Camada Tecnologia
Frontend React 17, Tailwind CSS, Zustand, React Three Fiber / Three.js, @dnd-kit, React Router
Backend Python 3.12, FastAPI, Pydantic, JWT (python-jose), bcrypt direto
Banco Turso (libSQL/SQLite na nuvem) via libsql-client, SQL puro, sem ORM
Outras libs reportlab, ezdxf, qrcode
Arquitetura: o React fala com o FastAPI por HTTP; só o backend acessa o banco. Os
módulos 3D ﬁcam serializados em JSON dentro do projeto.

4. Regras de negócio
1. Vãos recursivos: um vão pode ser dividido na vertical ou horizontal; cada divisão gera
dois vãos ﬁlhos. O painel divisório ocupa 15 mm, centrado na posição escolhida.
{ modulo_id, nome, dimensoes{largura,altura,profundidade},
estrutura{ divisoes[], internos[], portas[] }, aparencia{cor,
orientacao_fibra} }
2. Prateleiras empilháveis: um vão aceita várias prateleiras. N prateleiras geram N+1
compartimentos de altura igual (redistribuição automática). Ex.: guarda-sapato.
3. Gaveteiro exclusivo: um vão com gaveteiro não recebe prateleira nem divisão. Folga
de 3 mm entre gavetas.
4. Divisão exclusiva: um vão que já tem prateleira/gaveteiro não pode ser dividido.
5. Portas: só em vão sem divisão. Tipos: giro (lado da dobradiça), corrediça (par de folhas
com 15 mm de sobreposição) e báscula. Folga padrão de 3 mm em todo o contorno,
espessura de 18 mm.
6. Ferragens por peça: giro 2 dobradiças (3 se a altura passa de 1600 mm) + 1 puxador;
corrediça 1 kit de trilho + 2 puxadores; báscula 2 dobradiças de báscula + 1 puxador;
gaveta 1 par de corrediças (tamanho = profundidade do módulo) + 1 puxador.
7. Chapas: cada peça referencia uma chapa por chapaId. A cor mora no cadastro da
chapa (color picker), a cor do veio é calculada (~20% mais escura). Isso alimenta
nesting e preço.
8. Biblioteca: cada marceneiro vê só a própria biblioteca. Ao carregar um modelo em
outras dimensões, a estrutura é reescalada proporcionalmente.

Fase 6 — App mobile com Ionic/Capacitor (condicional)
Só entra se o cliente pedir. Tecnicamente viável: o React Three Fiber roda em WebView, e o
código React atual é reaproveitado.
Custos de loja: Google Play US$ 25 (único); Apple US$ 99/ano. Publicar no iOS exige
um Mac (Xcode).
O backend precisa estar hospedado com HTTPS (não pode ser localhost); a URL da
API vira variável de ambiente do build.
Sem internet o app não funciona (modo offline ﬁca fora do escopo).
O editor 3D precisa de layout revisado para toque/tablet.

7. Riscos e dependências
1. A etapa 2.9 precisa vir antes de 3.2, 4.1 e 4.5, porque todas assumem que as peças
estruturais existem.
2. O chapaId por peça é dado central: afeta visual (2.6), nesting (4.1) e preço (4.5).
3. Reescala de modelos da biblioteca exige salvar as dimensões originais junto com a
estrutura.
4. Os tipos de ferragem precisam ser fechados antes de a preciﬁcação consumir esse
vínculo.
